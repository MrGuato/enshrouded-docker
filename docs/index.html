Installation & Operations Guide

Enshrouded Dedicated Server on Linux

Deploy a self-updating, rootless-runtime Enshrouded Dedicated Server on any Linux machine in a single command. SteamCMD automatically updates the server on startup while keeping your world saves and configs safe on the host.

🚀 One-Shot Linux Install (Recommended)

On a fresh Ubuntu, Debian, Fedora, or Arch Linux machine, run this single command in your terminal:

bash — Standard One-Shot Install 
curl -fsSL https://raw.githubusercontent.com/MrGuato/enshrouded-docker/main/setup.sh | bash

Want to set your server name, player slots, and password right away? Pass them inline:

bash — Custom Name & Password One-Shot Install 
SERVER_NAME="Flameborn Server" SERVER_PASSWORD="mySecretPassword" SERVER_SLOTS=16 \
  curl -fsSL https://raw.githubusercontent.com/MrGuato/enshrouded-docker/main/setup.sh | bash

What setup.sh does automatically:

  • Installs dependencies: Installs git, curl, and Docker Engine + Docker Compose if not already present — without forcing you to log out and re-run.
  • Creates workspace: Sets up ~/enshrouded-docker with persistent folders matched to your Linux user's UID/GID (PUID/PGID).
  • Generates .env: Writes a clean .env file with your server settings.
  • Configures host firewall: Automatically opens UDP port 15637/udp (and 27015/udp) if ufw or firewalld is active.
  • Starts the server: Pulls ghcr.io/mrguato/enshrouded-docker:latest and starts the container in the background.
⏳ First-Run Download (~6 GB) On first launch, SteamCMD downloads the Enshrouded Dedicated Server binaries (~6 GB). Watch progress live with: cd ~/enshrouded-docker && docker compose logs -f. Look for [Session] 'HostOnline' (up) to know the server is ready!

🐳 Manual Setup (Docker Compose)

If you already have Docker and Docker Compose installed and prefer to set up the directory manually:

  1. Clone the repository and create your .env file:
    bash 
    git clone https://github.com/MrGuato/enshrouded-docker.git
cd enshrouded-docker
cp .env.example .env
  2. Edit .env to customize your server name, slots, or passwords:
    bash 
    nano .env
  3. Pull the image and start the container:
    bash 
    docker compose pull
docker compose up -d
docker compose logs -f

Reference docker-compose.yaml

docker-compose.yaml 
services:
  enshrouded:
    image: ghcr.io/mrguato/enshrouded-docker:latest
    container_name: enshrouded-server
    restart: unless-stopped
    stop_grace_period: 30s
    ports:
      - "${QUERY_PORT:-15637}:${QUERY_PORT:-15637}/udp"
      - "27015:27015/udp"
    environment:
      PUID: "${PUID:-1000}"
      PGID: "${PGID:-1000}"
      UPDATE_ON_START: "${UPDATE_ON_START:-1}"
      SYNC_CONFIG_ON_START: "${SYNC_CONFIG_ON_START:-1}"
      SERVER_NAME: "${SERVER_NAME:-My Enshrouded Server}"
      SERVER_SLOTS: "${SERVER_SLOTS:-16}"
      SERVER_PASSWORD: "${SERVER_PASSWORD:-}"
      ADMIN_PASSWORD: "${ADMIN_PASSWORD:-}"
      FRIEND_PASSWORD: "${FRIEND_PASSWORD:-}"
      GUEST_PASSWORD: "${GUEST_PASSWORD:-}"
      QUERY_PORT: "${QUERY_PORT:-15637}"
      ENABLE_VOICE_CHAT: "${ENABLE_VOICE_CHAT:-false}"
      ENABLE_TEXT_CHAT: "${ENABLE_TEXT_CHAT:-false}"
      GAME_SETTINGS_PRESET: "${GAME_SETTINGS_PRESET:-Default}"
    volumes:
      - ./enshrouded-config:/home/steam/config
      - ./enshrouded-server:/home/steam/server
      - ./enshrouded-wine:/home/steam/.wine

⚙️ Environment Variables Reference

Configure these variables in your .env file or directly in docker-compose.yaml. When SYNC_CONFIG_ON_START=1 (default), changes to these variables automatically update enshrouded_server.json on container restart while preserving any custom gameplay settings.

Variable Default Description
SERVER_NAME Enshrouded Docker Server Server name displayed in the in-game browser.
SERVER_SLOTS 16 Maximum concurrent player slots (1–16).
SERVER_PASSWORD (empty) Single password for all players. Leave empty for a public server.
ADMIN_PASSWORD (empty) Optional password for the Admin role (kick/ban + full base/inventory access).
FRIEND_PASSWORD (empty) Optional password for the Friend role (build/extend base + inventory access, no kick/ban).
GUEST_PASSWORD (empty) Optional password for the Guest role (explore/play without editing base or chests).
QUERY_PORT 15637 Primary UDP port used by Enshrouded for both game traffic and server queries.
ENABLE_VOICE_CHAT false Set to true to enable built-in voice chat.
VOICE_CHAT_MODE Proximity Voice chat mode (Proximity or Global).
ENABLE_TEXT_CHAT false Set to true to enable in-game text chat.
GAME_SETTINGS_PRESET Default Difficulty preset: Default, Relaxed, Hard, Survival, or Custom.
UPDATE_ON_START 1 Run SteamCMD on startup to update the server (0 to skip).
SYNC_CONFIG_ON_START 1 Sync environment variables into enshrouded_server.json on startup (0 to manage JSON exclusively by hand).
PUID / PGID 1000 / 1000 Host user/group ID for volume ownership so you never hit permission errors on the host.

🔐 Passwords & Role-Based User Groups

Enshrouded uses role-based userGroups in enshrouded_server.json. This container supports two simple modes via environment variables:

Mode 1: Single Password for Everyone

Set SERVER_PASSWORD in .env (and leave ADMIN_PASSWORD, FRIEND_PASSWORD, GUEST_PASSWORD empty). Every player joins with that password and gets full building/inventory permissions.

Mode 2: Multi-Role Passwords (Admin / Friend / Guest)

Set any combination of ADMIN_PASSWORD, FRIEND_PASSWORD, and GUEST_PASSWORD in .env. Players join the server using the password for their role:

  • Admin (ADMIN_PASSWORD): Can kick/ban players, access chests, edit and extend bases.
  • Friend (FRIEND_PASSWORD): Can access chests, edit and extend bases (cannot kick/ban).
  • Guest (GUEST_PASSWORD): Can play in the world, fight bosses, and quest, but cannot open chests or modify bases.
💡 Editing enshrouded_server.json Directly If you want to customize granular gameSettings (such as enemy health, resource drop multipliers, or day/night length), stop the container first (docker compose down), edit ./enshrouded-config/enshrouded_server.json, and start it again (docker compose up -d). Enshrouded overwrites the JSON file on shutdown if edited while running!

🌐 Ports, Firewall & Connecting

Enshrouded uses UDP port 15637 for both game traffic and Steam server browser queries.

Linux Host Firewall

If you used setup.sh, firewall rules were added automatically. To open the ports manually:

bash — UFW (Ubuntu / Debian) 
sudo ufw allow 15637/udp
sudo ufw allow 27015/udp
bash — firewalld (Fedora / RHEL / Rocky) 
sudo firewall-cmd --permanent --add-port=15637/udp
sudo firewall-cmd --permanent --add-port=27015/udp
sudo firewall-cmd --reload

How to Connect In-Game

  1. In Enshrouded: Click Play → Join → Search for your SERVER_NAME or click Search by IP and enter <YOUR-SERVER-IP>:15637.
  2. Via Steam Server Browser: Open Steam → View → Game Servers → Favorites → click + and add <YOUR-SERVER-IP>:15637.

💾 Data Persistence, Backups & Restore

All server files live in three folders inside your installation directory (~/enshrouded-docker/):

Directory Layout 
enshrouded-docker/
├── enshrouded-config/
│   ├── enshrouded_server.json   # Server configuration
│   ├── savegame/                # World save files (back this up!)
│   └── logs/                    # Enshrouded server logs
├── enshrouded-server/           # SteamCMD game binaries (~6 GB cached)
└── enshrouded-wine/             # Wine64 prefix cache

Create a World Backup

bash — Backup savegame directory 
cd ~/enshrouded-docker
tar -czf "enshrouded-backup-$(date +%Y%m%d-%H%M%S).tar.gz" -C enshrouded-config savegame enshrouded_server.json

Restore / Upload a Local Singleplayer World

  1. Stop the container: docker compose down
  2. Copy your world save files (e.g. 3ad85aea and 3ad85aea-index) into ./enshrouded-config/savegame/
  3. Start the container: docker compose up -d

🛠️ Day-2 Operations & Updating

Update the Game After an Enshrouded Patch

Because UPDATE_ON_START=1 is enabled by default, simply restart the container and SteamCMD will download the patch automatically:

bash 
cd ~/enshrouded-docker
docker compose restart
docker compose logs -f

Update the Docker Image

bash 
cd ~/enshrouded-docker
docker compose pull
docker compose up -d

Stop the Server Safely

Stopping the container sends a graceful shutdown signal to Wine and waits for Enshrouded to flush world saves to disk:

bash 
cd ~/enshrouded-docker
docker compose down

🩺 Troubleshooting

1. Server does not appear in the browser

  • Wait until the first-time ~6 GB SteamCMD download finishes. Run docker compose logs -f and verify you see [Session] 'HostOnline' (up).
  • Check that UDP port 15637 is open on your Linux firewall (sudo ufw status) and your cloud provider's Security Group (AWS, Oracle, Hetzner, DigitalOcean, etc.).
  • If hosting at home, ensure your router forwards UDP 15637 to your Linux machine's LAN IP.

2. Password or Server Name changes aren't applying

  • Make sure SYNC_CONFIG_ON_START=1 is set in .env, then recreate the container with docker compose up -d (note: docker compose up -d reloads .env, whereas docker compose restart does not reload changed .env files).

3. Corrupted Wine Prefix

If Wine fails to initialize after a host crash, reset the Wine prefix volume (your saves and game files will not be affected):

bash 
cd ~/enshrouded-docker
docker compose down
rm -rf ./enshrouded-wine
docker compose up -d
